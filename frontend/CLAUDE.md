# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Scope and role boundary

This directory (`oa-agent/frontend/`) is the Vue 3 UI for the "企业 OA 文件智能归档智能体" project. The backend (Go API, Python document worker, `contracts/`, `migrations/`) is written by Codex in the sibling directories. **Only edit `frontend/`.** Never change Go/Python/migrations/OpenAPI; if an endpoint or field is missing, record it in `CONTRACT-GAPS.md` instead of inventing it. The task briefs live in `../../oa-agent-starter/` (`02-Claude-纯UI任务书.md` is the UI spec; `03` is the contest acceptance checklist R01–R14; `04` is the contract baseline).

Repo-wide conventions (backend/worker/contract commands, style, PR expectations) are in `../AGENTS.md`; this file only adds frontend specifics. Style there applies here: two-space indent, TypeScript single quotes, no semicolons, PascalCase Vue filenames. Contract edits happen only in `../contracts/openapi.yaml` (Codex's), then it is synced to the Go embed.

Product principle: AI auto-archiving first, not a chat app. The natural-language correction drawer is optional, per-file, and only applies after the user confirms a before/after diff.

## Commands

Run from `oa-agent/frontend/`:

```bash
npm install
npm run dev                          # Vite on :5173, proxies /v1 /healthz /readyz to OA_API_TARGET (default http://127.0.0.1:8080)
npm run build                        # vue-tsc --noEmit && vite build (this is also the typecheck gate)
npm run typecheck
npm test                             # vitest run (node env, src/**/*.test.ts)
npx vitest run src/utils/format.test.ts      # single file
npx vitest run -t "rejects traversal"        # single test by name
```

Environment quirk: in WSL there is no Linux Node; use the Windows one, e.g. `cmd.exe /c "cd /d D:\OA Files Agent\oa-agent\frontend && npm run build"` (with `/mnt/c/Program Files/nodejs` on PATH). Pipe output through bash `tail` outside the `cmd.exe /c` string, not inside it.

TypeScript is pinned to `~5.9`: TS 7 breaks `vue-tsc`. There is no linter configured.

## Architecture

**Api interface with two interchangeable implementations.** `src/api/types.ts` defines every domain type *and* the `Api` interface. `src/api/index.ts` exports `api` as a Proxy that picks `realApi` (`real.ts`) or `mockApi` (`src/mocks/mockApi.ts`) per call, based on `VITE_USE_MOCK` or the `oa.useMock` localStorage flag; toggling reloads the page so real and demo data never mix. Views only ever import `api` and types from `../api`. `src/api/` is HTTP/SSE only; `src/mocks/` is demo only. `.env.development` defaults to mock (persistent banner in `App.vue`); production builds default to real and are served by the Go API (`OA_FRONTEND_DIR`) so no proxy is needed. `npm run e2e`-style browser checks live in `e2e/ui.mjs` (puppeteer-core + Edge/Chrome; configure with UI_BASE, UI_SAMPLES, UI_BROWSER).

**Types come from the contract.** `src/api/schema.d.ts` is generated from `../contracts/openapi.yaml` (`npm run gen:api`); `types.ts` only aliases them and holds the `Api` interface. After a contract change regenerate, then let `vue-tsc` point at what to adapt (the mock drifting is caught the same way). `realApi` follows the implemented contract: `paths` manifest first then `files` for imports, `Idempotency-Key` on execute, `version` on patch/approve.

**Mock fidelity matters.** `mockApi` simulates the task state machine (`queued → scanning → extracting → analyzing → planning → awaiting_review → approved → archiving → completed`) with timers and SSE-style events, and enforces the same rules as the contract: execute requires an approved plan (idempotent), patch/approve use `version` with 409 on conflict, approve is refused while any item has `review_required`. Keep it consistent with the real semantics when changing either side.

**Core UX invariants** (from the contract/brief, enforced in `PlanView.vue`): approval and execution are separate buttons; execute sends an `Idempotency-Key`; undetermined fields display "待审核" and are never fabricated; relative paths from folder import are normalized and `..`/absolute paths rejected client-side (`src/utils/paths.ts`) though the backend must still validate. Browsers can only upload user-selected files, not arbitrary local paths.

**SSE** (`src/api/sse.ts`) uses a fetch stream (not `EventSource`) with `Last-Event-ID` resume and exponential reconnect; `TaskDetailView` dedupes by monotonic event `id`. Error bodies follow `{error:{code,message,request_id}}` and surface as `ApiError`; `useAsync` (`src/utils/useAsync.ts`) is the shared loading/error/data helper and `StateView.vue` renders the loading/empty/error states.

**Theming.** `src/theme/theme.ts` generates an M3 scheme from a seed color via `@material/material-color-utilities` and writes `--md-sys-color-*` variables onto `:root`; `src/styles/base.css` holds all other tokens (shape, elevation, success/warn colors, surface-container roles are written by `theme.ts` from the neutral palette, state-layer/motion/type-scale tokens live in `base.css`) plus the shared component classes (`.btn`, `.chip`, `.card`, `.tbl`, `.banner`, `.seg`, …). Views use these global classes and keep only layout in scoped styles. Icons are inline SVG (Material Symbols, see "Icons" below), so there is no icon font and everything works offline.

Routing is in `src/router/index.ts` (lazy views; `meta.parent` keeps the sidebar highlight on detail routes). Contract gaps and the assumed shapes for templates, ledger, plans, corrections, etc. are tracked in `CONTRACT-GAPS.md`; update it when you add or change a frontend assumption.

## Login and accounts (auth architecture)

Contract tags `setup`, `auth`, `admin-users`; spec in `../docs/auth-design.md`. Everything below is frontend-only.

- **Transport** (`src/api/http.ts`): all requests use `credentials: 'same-origin'` (session cookie `oa_session` is HttpOnly, invisible to JS). The CSRF token lives only in a module variable (`setCsrfToken`, filled from login/`getMe`/reauth/enrol responses) and is sent as `X-CSRF-Token` on every non-GET. Global handling lives in `raw()`: `403 CSRF_INVALID` → `refreshCsrf` hook (`getMe`) then one retry; `401 UNAUTHENTICATED` → `onUnauthenticated` hook (skipped when `silent`, e.g. login/me probe); `503 SETUP_REQUIRED` → `onSetupRequired`; `429`/`423` messages are rewritten with Retry-After / lock info (`utils/authErrors.ts`). `ApiError.retryAfter` carries seconds. SSE (`sse.ts`) is a same-origin cookie fetch; 401/503 call the same hooks. Hooks are installed in `src/auth-install.ts` (avoids api→router cycles).
- **State** (`stores/auth.ts`, Pinia): `setup` (public `GET /setup/status`), `me`, `policy` (only known after login: the contract has no public policy endpoint), `can(role)`, `withReauth(fn)` (pre-prompts when `me.fresh === false`, retries once after a 403 reauth signal; the dialog is `ReauthDialog` driven by `reauthPrompt`). `init()` runs before the first navigation.
- **Guard** (`utils/authz.ts` `guardDecision`, pure and unit-tested; wired in `auth-install.ts`): not initialised → `/setup`; initialised → `/setup` bounces (except while finishing MFA enrolment); public routes (`meta.public`) open; no session → `/login?redirect=` (`safeRedirect` allows only same-site paths); `scope=enroll_mfa` or `must_change_password` → `/account/security` (`meta.allowRestricted`); `meta.minRole` otherwise → `/forbidden`. Nav (`NAV[].minRole`, `ADMIN_NAV`) and write buttons are filtered with `auth.canWrite` / `auth.isAdmin`; the backend is authoritative.
- **Pages**: `LoginView` (password, discoverable Passkey + conditional UI, MFA chooser TOTP/Passkey/recovery), `SetupView` (7-step wizard, 8 with the later-added LLM step in enterprise mode; `complete` is called at the end of the policy step, then MFA enrolment and one-time recovery codes, LLM (explicit skip) and a final 完成 step that calls `POST /v1/setup/finish`; the wizard is a server-side gate (`wizard_finished`, 409 `WIZARD_REQUIRED`) and resumes from server state via `resumeStep`; non-secret form state in sessionStorage only, never password/token), `InviteView`, `AccountSecurityView`, `AdminUsersView`, `AdminSecurityView`, `AdminSessionsView`, `AdminAuditView`, `ForbiddenView`. App shell hides itself on public routes and has the user menu.
- **One-time secrets** (temporary password, invite link, recovery codes): `utils/oneTime.ts` state + `OneTimeSecret`/`OneTimeDialog`; the dialog cannot be closed until copied/acknowledged (recovery codes: explicit checkbox) and the plaintext is wiped on close. No `v-html`; QR codes are rendered locally by `qrcode` into a `data:` image.
- **WebAuthn**: `utils/passkey.ts` wraps `@simplewebauthn/browser`; `utils/webauthn.ts` has availability reasons and error→message mapping. Demo mode (`api.capabilities.webauthn === false`) returns placeholder credentials instead of touching the browser.
- **Mock** (`src/mocks/mockAuth.ts`): in-memory users/sessions/settings. Auto-logged-in demo admin (not "fresh", so the reauth dialog is demonstrable); `admin`/`operator`/`viewer`, password `demo-password`, TOTP `123456`, recovery `DEMO1-DEMO2`; lockout, LAST_ADMIN, reauth, RP-change confirmation are enforced like the contract. `?mock_setup=1` shows the wizard.
- **E2E**: `e2e/ui_auth.mjs` (virtual authenticator, TOTP via `e2e/lib/totp.mjs`) and the optional login step in `e2e/ui.mjs`.

## AI workbench, automation, diagnostics and error handling

Contract tags `ai` and `diagnostics` (plus `admin` for `/v1/admin/ai-policy`). Product rule stays: the AI workbench is a **task-assignment UI, not a chat**; documents are data, never instructions.

- **LLM status** (`stores/ai.ts`, `utils/aiStatus.ts`): `GET /v1/llm/status` is the single source for “can this user use the AI” (`configured`, `source` global/personal, `setup_hint`, `auto_archive_allowed`, `auto_ack_version/text`). `statusView()` turns it into the chip (“将使用：全局 · 模型”) or the unmissable no-LLM card + CTA (`admin_global` → `/settings#llm`, `personal_or_admin` → personal config + “联系管理员”, `contact_admin` → text only). `LlmStatusBanner.vue` renders it; `effectiveSourceLine()` is the settings status line. Refresh the store after any save/delete/policy change (`LlmSettings` and `AiPolicyCard` do).
- **Fully automatic mode** (`utils/automation.ts`): `useAutomation(status, role)` is the state machine behind the “人工审核 | 全自动” `AutomationSelector`: selecting 全自动 opens `AutoRiskDialog` (role=alertdialog via `Dialog`'s `alert` prop; shows `auto_ack_text` verbatim; confirm needs the checkbox AND a 3 s countdown; Esc/cancel reverts to 人工审核). The acknowledgement is kept in a **module variable only** (per page load and per `auto_ack_version`; never localStorage/sessionStorage/cookies). `buildImportOptions()` builds `ImportOptions` (and refuses an `auto` payload without an ack version); `automationGate()` explains why 全自动 is disabled (role / no LLM / policy). Server errors `AUTO_ARCHIVE_DISABLED`, `AUTO_ACK_REQUIRED`, `LLM_REQUIRED`, `PERSONAL_LLM_DISABLED` are mapped in `utils/errorInfo.ts` (`knownErrorMessage`) and the views refresh the status after them.
- **Import options on the wire**: `api/importForm.ts` builds the multipart body in the contract order `paths` → `options` (only when non-empty) → `files…`; remote imports send `options` in the JSON body. `ImportOptions` is `Partial<>` of the generated type (the generator marks defaulted fields required).
- **Pages**: `AiWorkbenchView` (composer + task thread, `AiTaskCard` with live `AgentTrace` SSE, auto-run summary derived by `utils/autoSummary.ts` from files + plan, “撤销本次全自动归档” → `rollbackOperation(plan.operation_id)`), `ImportView` (shares `FilePicker` — 100 files / 20 MiB / 128 MiB rules in `utils/importLimits.ts` — plus the mode selector and optional instruction), `DiagnosticsView` (admin; `stores/diag.ts` refreshes `GET /v1/admin/system` every 60 s for the nav badge), `SettingsView` (anchor `#llm`), `SetupView` (new `llm` step after MFA for enterprise mode; local mode has none).
- **LLM simple mode** (default; advanced = the old form, remembered in `localStorage oa.llm.ui`): `LlmSimple.vue` (provider cards, paste/login/local steps, auto test + model pick, one save) driven by pure `utils/llmGuide.ts` (guides per provider, key-format check, clipboard chip, step reducer, connection summary) and `utils/llmError.ts` (provider failure classification + retry/Retry-After label, shared with `LlmFailureBanner.vue` which every provider-call failure uses). `LlmLoginPanel variant="simple"` shows “Key created: label” (`LlmConfig.key_label`). Mock faults by key text: see `mocks/mockAi.ts` (`sk-bad`, `sk-down`, `sk-flaky`, `sk-limit`); `?mock_oauth_test=fail`. Visual sweep: `e2e/ui_llm.mjs`.
- **LlmSettings** is one component for both scopes (`scope='global'|'personal'`, optional `fns` override, `embedded` for the wizard). Global keeps the old ids/test ids (`#llm-base`, `llm-engine`, …); personal uses `pllm-*` / `personal-llm-*`. Personal has no “离线规则” mode and a delete action; 422 gets the stricter-address hint (`llmErrorText`).
- **Settings route** is now `minRole: operator` (operators need the personal LLM card); admin-only sections (global LLM, AI policy, service data source, audit) are hidden by role. The backend stays authoritative.
- **Ledger / files**: `DecisionBadge` (“人工审核” neutral / “全自动 · 模型” warning tint). Ledger has a 决策方式 column and a “仅全自动” switch (sends `decision=ai_auto`, not in the contract, and also filters the page client-side). `FileRecord` has no decision field, so file details derive it from the owning task (`automation==='auto'`).
- **Errors** (`utils/errorInfo.ts`): `describeError`/`errMsg` give every API error “（请求编号 xxx）”; 5xx → “服务器内部错误，已记录，请联系管理员并提供请求编号”; network failures → `NETWORK_HELP`. `StateView` and `ErrorBanner` split the id out and offer “复制错误信息”; error toasts containing a request id get a copy button automatically (`stores/ui.ts` toast `action`).
- **Global error reporting** (`errorReporting.ts`, `utils/errorReporter.ts`): Vue `errorHandler`, `window.onerror`, `unhandledrejection` → `createReporter` (dedupe identical messages 60 s, ≤5 reports/min, scrubs URLs/tokens/long random strings, truncates, sends only message/stack/route/component/app_version; ignores `ApiError`, network TypeErrors, ResizeObserver noise; only when logged in) → `POST /v1/client-errors` and a toast “页面出现了问题，已记录（编号 xxxx）” with “复制详情”. `RouteErrorBoundary` wraps the route view (retry button + report id; it reports silently itself and stops propagation to avoid double reports). `window.__oaTestError()` / `__oaTestRejection()` exist **only under `import.meta.env.DEV`** (never in production builds).
- **Backend-down banner** (`utils/backendHealth.ts`, `BackendBanner.vue`): `api/http.ts` calls a network hook when `fetch` itself fails; the monitor then polls `/healthz` every 5 s and clears itself when it answers. Not triggered in demo mode.
- **Mock layer**: `mocks/mockAi.ts` (status variants via `?mock_llm=none|global|personal`, default `global` in the browser and `none` under vitest; policy; personal config with the stricter address rule and a 429 on >6 tests/min; import-option validation incl. all error codes), `mocks/mockDiag.ts` (reports with an unclean-exit sample, `?mock_unclean=0` hides it, `?mock_disk=low` shows the disk warning; client-error aggregation; bundle as a small text blob), `mockApi` auto-run flow (`autoExecute`: archives confident items with `decision: 'ai_auto'`, leaves `review_required` ones in the plan; one seeded automatic task for the undo demo). Role comes from the existing mock auth (log out and sign in as `operator`/`viewer`).
- **E2E (not run in CI)**: `e2e/ui_ai.mjs` (needs `UI_FAKE_LLM_URL`), `e2e/ui_diag.mjs` (client-error part needs the Vite dev server, see its header), shared helpers in `e2e/lib/common.mjs`. `ui_auth.mjs` skips the new wizard LLM step.

## Icons

- Icon set: **Material Symbols, Outlined, weight 400, grade 0, optical size 24** (npm `@material-symbols/svg-400`, Apache-2.0), the standard M3 set. Glyph path data is bundled offline in the generated `components/iconGlyphs.ts` (no icon font, no CDN, only mapped icons ship).
- Call sites use `<Icon name="folder_open" sm />`. `components/Icon.vue` resolves the name through **`components/iconMap.ts`** (`NAMES`: UI name -> Material Symbols glyph name; includes legacy/semantic aliases such as `trash`, `spinner`, `ai`). To add an icon: add `ui_name: 'material_symbol_name'` to `NAMES` (names at fonts.google.com/icons), add it to `FILLED` if it needs a filled variant, run `npm run gen:icons`, commit `iconGlyphs.ts`.
- `<Icon fill>` selects the filled glyph (selected navigation item, status icons, folders) when the glyph is in `FILLED`; otherwise the outlined glyph is used. Size is `1em` of `.icon` (24px; `sm` 18px; `md` 20px), colour is `currentColor`. Decorative by default (`aria-hidden`); pass `label="..."` to expose it.
- Unknown names render a neutral circle and log one `console.warn` in DEV. `components/iconMap.test.ts` scans `src/**/*.{vue,ts}` for icon names, fails if one is unmapped, and fails if another icon library is imported.
- E2E scripts must not match icons by their text: use aria-labels / `data-testid`.
- Visual rules, tokens and component inventory: `../docs/界面规范-Material3.md`.
