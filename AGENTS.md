# Repository Guidelines

## Project Structure & Module Organization
- `backend/`: Go API on Gin (router, recovery, CORS only; handlers stay `net/http`, path params via `r.PathValue`; CORS allow-list `OA_CORS_ORIGINS`, exact origins, never `*`). Auth: Deps.Auth nil = no authn (unit tests only); `OA_PUBLIC_URL`, `OA_TRUSTED_PROXY=1`; setup token is printed as `SETUP TOKEN:` at every start while uninitialised. `cmd/oa-agent` (server + standalone launcher), `cmd/migrate`, `cmd/oa-admin` (break-glass CLI: setup-token, reset-password/mfa, unlock, create-admin; audited as `oa-admin(cli)`), `cmd/e2e` (end-to-end acceptance driver), `cmd/contract-samples`. `api` (HTTP, SSE, Excel export; `authz.go` holds the single route→minimum-role table, default deny, with a test over every route)`, `auth` (login/accounts without HTTP: argon2id, TOTP, recovery codes, sessions/CSRF, rate limit/lockout, WebAuthn, setup wizard, user admin; `auth/softauth` is a test authenticator), `store` (PostgreSQL), `pipeline` (durable queue, planning, execute/rollback), `harness` (Agent loop, tools, providers, rules), `diag` (error reports, redaction, panic-safe goroutines, crash files, run lock), `archive` (naming, conflict handling, atomic publish, rollback), `imports` (multipart intake), `llm` (engine presets, saved config, hot-swap provider, test, model list, `oauth.go`: PKCE "sign in with the platform" for OpenRouter only, in-memory single-use state, public callback `GET /v1/llm/oauth/callback`, key provenance tag inside the sealed blob; see `docs/LLM账号登录配置.md`), `secrets` (AES-GCM for saved API keys), `fsman` (safe file-manager paths, trash), `fileops` (file manager + ledger sync, Windows Explorer reveal), `cloud` (optional storage providers: s3, azure_blob, webdav, sftp, ftp, smb, dingtalk; add-only `PutNew`), `storage` (connections, remote import, replication worker), `dbtest` (isolated test schemas), `supervisor` (worker + embedded PostgreSQL), `db`, `worker`.
- `workers/document-ai/`: Python 3.12 extraction/OCR worker (`server.py`, `extract_core.py`, `worker_main.py` for PyInstaller) and unittest suite.
- `frontend/`: Vue 3 + TypeScript + Vite. `src/api/schema.d.ts` is generated from the contract (`npm run gen:api`); `src/mocks/` is demo data only; `e2e/ui.mjs` drives a real browser.
- Releases: tag `v<VERSION>` triggers `.github/workflows/release.yml` (Windows x64+arm64 installer/portable/server zips, Linux amd64+arm64 tarballs, one `SHA256SUMS`); asset names live only in `scripts/release-assets.sh`, tag must equal `VERSION`, arm64 Windows worker/PostgreSQL are x64 (see `docs/构建与发布.md`); offline tests `bash scripts/test/release.sh`.
- `contracts/openapi.yaml` is the only contract source; `contracts/events.md` documents SSE. `migrations/`, `deploy/` (Docker, Windows package), `scripts/`, `docs/`, `tests/samples/` (labelled fixtures).
- Databases: PostgreSQL (default), MySQL 8.0+ and SQL Server 2019+ via `internal/sqldb` (dialect + SQL translator), `internal/dbconfig`, `internal/dbadmin` (`/v1/admin/database*`), per-dialect `migrations/{,mysql,mssql}`; matrix tests `scripts/test-db-matrix.sh` (`OA_TEST_DATABASE_URL`/`OA_TEST_MYSQL_URL`/`OA_TEST_MSSQL_URL`); cross-database data migration is NOT implemented; see `docs/多数据库部署与迁移指南.md`.

## Build, Test, and Development Commands
- Dev environment (Windows: `powershell -ExecutionPolicy Bypass -File scripts\dev.ps1 up|down|status|logs|token|reset`, downloads a private PostgreSQL on :54320; Linux/macOS/WSL: `scripts/dev.sh`): `scripts/dev.sh up [--mock]` / `down [--all]` / `status` / `logs [api|worker|web|pg]` / `token` / `reset` (PostgreSQL + worker + API debug build + Vite; state in `data/dev/`; open `http://localhost:5173`).
- `backend/`: `go run ./cmd/oa-agent`; `go run ./cmd/migrate -dir ../migrations`; `go vet ./...`; `go test ./...` (set `OA_TEST_DATABASE_URL` to a disposable PostgreSQL to run the store/pipeline/db integration tests; they skip otherwise).
- `workers/document-ai/`: `python -m unittest -v` (needs `pip install -r requirements.txt`).
- `frontend/`: `npm ci`, `npm run dev`, `npm run build` (typecheck + build), `npm test`, `npm run gen:api` after any contract change.
- File manager: all on-disk paths go through `fsman` (validated, symlink-safe, no overwrite); every mutation must also keep `ledger_entries` in sync via `fileops`. `OA_ALLOW_REVEAL=0` disables the Windows Explorer launch.
- Contract: edit `contracts/openapi.yaml`, run `python scripts/sync_contract.py`, then `python scripts/check_contracts.py` (add `--recorded <file>` with responses captured by `go run ./cmd/e2e -record <file>`).
- Container images: `.github/workflows/images.yml` builds `api`, `worker` and `deploy` (installer bundle: `deploy/docker/Dockerfile.deploy`, `/deploy` with install.sh, oa-agentctl.sh, compose files, prebuilt oa-agentctl + SHA256SUMS) on every push/tag and pushes them to the registry from the `ACR_*` Actions secrets/variables (never in the repo; PRs and forks only build); tag rules also in `scripts/push-images.sh`. `install.sh --registry HOST[/NS] [--image-tag T]` installs from those images (no build, bundle taken from `oa-agent-deploy`), `oa-agentctl upgrade [--tag T]` pulls + refreshes management files; see `docs/部署指南-Linux.md` §11. Installer hardening (§12, `docs/安装脚本对比-1Panel.md`): `install.sh --check` (read-only pre-flight report), `--offline <tar>` with `scripts/save-images.sh` (docker-save bundle + SHA-256), `--reinstall`, `--docker-mirror`; exit codes 0/1/2/3 (pre-flight failed)/4 (cancelled)/130; offline tests `bash deploy/linux/test/run.sh`.
- Go build modes: `scripts/build-backend.sh [debug|release]` or `scripts\build-backend.ps1 -Mode debug|release` (output `backend/bin`). Debug = `-tags debug` (enables `logx.Debugf`, unoptimised for dlv, version/commit via ldflags); release = `-trimpath -s -w`, debug logging compiled out. Debug lines log IDs/status/durations only, never secrets or document text; `OA_LOG_LEVEL=info` silences them at run time. Run `go test -tags debug ./...` too when touching logging.
- Windows package: `powershell -ExecutionPolicy Bypass -File deploy\windows\build.ps1`.
  (add `-Mode debug` for a debug package)

## Coding Style & Naming Conventions
`gofmt` for Go; four-space indentation and snake_case for Python; two-space indentation, single quotes, no semicolons for Vue/TypeScript; PascalCase Vue filenames. No frontend linter is configured. Keep the PowerShell build script UTF-8 with BOM (Windows PowerShell 5 otherwise garbles Chinese literals).

## Testing Guidelines
Go `*_test.go`, Python `test_*.py`, Vitest `*.test.ts`. Behavioural coverage for changed logic; no numeric threshold. Real-file checks: `go run ./cmd/e2e` (needs running API + worker + PostgreSQL) and `frontend/e2e/ui.mjs`. After changing the API, re-record e2e responses and re-run the contract check so the documented schemas stay true.

## Commit & Pull Request Guidelines
No Git history here. Use concise imperative subjects. PRs describe behaviour changes, report validation and anything skipped, and include screenshots for UI changes (`frontend/e2e/screenshots/`).

## Security & Configuration
Keep secrets out of commits and logs. API and worker share a random `OA_WORKER_TOKEN` (and spool root); the standalone launcher generates both. Go does not load `.env`; the standalone launcher reads `oa-agent.env` (OA_* keys only). Never give the model shell or write access: all file writes go through `internal/archive`. Document text is data, never instructions. Distinguish demo data (`VITE_USE_MOCK`) from real backend behaviour.
