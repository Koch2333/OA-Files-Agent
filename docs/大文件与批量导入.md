# 大文件与批量导入

导入**没有产品层面的文件大小、整批大小或文件数量上限**。早期版本的“每批 100 个文件、单文件 20 MiB、整批 128 MiB”已经取消；超大文件改用另一种机制传输（可续传的分片上传，或桌面版的本机路径导入）。

## 1. 三种导入方式

| 方式 | 适用 | 特点 |
|---|---|---|
| 可续传分片上传 | 浏览器（企业 Web 版、桌面版均可） | 每个文件拆成 8 MiB 分片（服务端接受任意大小），失败自动退避重试，页面刷新/断网后从服务器已收到的位置继续；3 个文件并行；显示总进度、速度、剩余时间 |
| 本机路径导入 | **仅 Windows 桌面版（local 模式）** | 界面里“从本机选择文件/文件夹（免上传）”：后端直接按路径流式**复制**到暂存区，不经过 HTTP 上传；源文件只读，绝不移动或修改 |
| 一次性 multipart | 脚本、小批量 | `POST /v1/imports`，与旧契约相同，但没有大小上限，服务端边收边写盘（恒定内存） |

界面会自动选择：不超过 100 个文件且总计不超过 32 MiB 时用一次 multipart；否则用分片上传。桌面版里能拿到本机真实路径的单个文件走本机路径导入。

## 2. 服务端如何保证可靠

- **流式落盘**：请求体不整体缓冲；每个文件先写 `.part` 临时文件，同时计算 SHA-256，完成后原子重命名；中断或出错时临时文件被清理。
- **可续传**：`POST /v1/imports/uploads` 创建会话 → `PUT /v1/imports/uploads/{id}?offset=N` 追加（offset 必须等于服务器已收到的长度，不一致返回 409 并给出当前 offset；重复分片是幂等的）→ `POST …/complete` 校验大小与 SHA-256（以服务端摘要为准；客户端若声明了 sha256 且不一致，返回 422，文件作废需重传）→ `POST /v1/imports/batches/{batch}/commit` 一次提交成一个任务。`HEAD/GET …/uploads/{id}` 查询当前 offset。
- **过期清理**：会话 24 小时无活动后过期并由后台清理（`OA_UPLOAD_SESSION_TTL_HOURS`）；`DELETE` 可主动取消。崩溃遗留的半成品目录同样会被清理。
- **超时**：只有“连接停滞”（2 分钟内没有收到任何字节）才会断开，慢但持续的上传不会被超时打断。
- **提交保持幂等**：commit 与 multipart 一样支持 `Idempotency-Key`。

## 3. 仅有的保护

1. **磁盘空间检查（始终开启）**：在接收之前（创建会话、每个分片、multipart 的 Content-Length、本机复制）检查数据卷剩余空间，不足时返回 HTTP 507：“磁盘空间不足：需要 X，剩余 Y”。始终为系统保留一部分空间，默认 512 MiB（`OA_DISK_RESERVE_BYTES`）。**请按“待导入文件总大小 + 归档副本”规划磁盘**：原文件先进入暂存区（spool），归档时再复制到归档目录。
2. **可选的管理员安全阀（默认关闭）**：`OA_MAX_UPLOAD_BYTES`（单文件上限，字节）、`OA_MAX_BATCH_FILES`（每批文件数上限）。默认空或 0 = 不限制。它们是运维用的保险阀，不是产品限制；超过时对应文件作为失败项（`FILE_TOO_LARGE`）或整批被拒（`TOO_MANY_FILES`）。当前生效值可在 `GET /v1/imports/config` 看到（`null` = 不限制）。
3. 防滥用的会话数量上限（每批 5000 个未完成会话），远高于正常使用。

## 4. 超大文件如何识别

接收和识别是两件事。文件无论多大都会被**完整接收、计算 SHA-256、保留原件**。识别阶段有保护，防止拖垮解析服务：

- 文档解析服务对**全文提取/OCR** 设有大小保护：默认超过 256 MiB 的文件不做全文提取（`OA_EXTRACT_MAX_BYTES`，字节，0 = 不设保护）。
- 超过保护线的文件**不会失败**：系统只按文件名/元数据判断，并标记为“**待人工审核**（元数据判断）”，证据里写明“文件较大，已跳过全文识别”。审核页里你可以手动指定部门/类型/日期后正常归档。
- 即使在保护线以内，解析也只读取有限内容：PDF 最多读取前 300 页、OCR 最多前 50 页、Excel 最多前 5000 行，单次解析有超时。因此“认出来的依据”来自文档的开头部分，这是设计取舍而不是错误。
- 预览同理：超过保护线的文件无法在线预览，请在文件管理里下载/定位后用本机软件查看。

“待人工审核”的含义：系统没有足够依据自动决定，需要人确认后才会进入归档计划；文件本身已经安全保存，不会丢失。

## 5. 反向代理

- **Caddy**：默认没有请求体大小限制，也不会把请求体缓冲到磁盘。仓库的 `deploy/linux/Caddyfile.template` 已把 `response_header_timeout` 设为 0（API 读完整个 multipart 之后才会返回响应头，旧的 10 分钟会切断超大上传）。不要加 `request_body { max_size }`。
- **nginx**：必须取消默认的 1 MB 限制并关闭请求缓冲：

  ```nginx
  client_max_body_size 0;          # 不限制请求体大小
  proxy_request_buffering off;     # 边收边转发，不先把整个请求写到代理的磁盘
  proxy_buffering off;             # SSE（任务进度）需要
  proxy_read_timeout 3600s;
  proxy_send_timeout 3600s;
  ```

  分片上传每个请求只有 8 MiB，即使保留 `client_max_body_size 16m` 也能工作（浏览器端上传自动走分片）；但 multipart 与本机脚本需要上面的设置。
- **1Panel / 宝塔 / 其它**：同样找到“最大请求体/Client Max Body Size”设为 0 或足够大，并关闭请求缓冲、延长读写超时。CDN/WAF 前置时请确认其单请求体积上限（常见 100 MB–几百 MB）：分片上传默认 8 MiB 可绕过。
- 仍需 `OA_TRUSTED_PROXY=1`、`OA_PUBLIC_URL`（见《部署指南-Linux》）。

## 6. 本机路径导入（桌面版）

- 只在 **local（本机单用户）模式**、且请求来自本机回环地址、没有经过代理时可用（`POST /v1/imports/from-paths`）；企业模式一律返回 403 `LOCAL_ONLY`，`GET /v1/imports/config` 的 `local_path_import` 为 false。
- 递归遍历文件夹；符号链接/联接点不会被跟随，目录循环会被检测并跳过；默认跳过隐藏/系统文件和 Office 临时文件（`~$…`）。
- 拒绝设备路径（`\\.\…`）和应用自身数据目录；允许 UNC 共享（`\\服务器\共享`），按只读源处理。Windows 长路径由 Go 运行时自动处理。
- 单个文件读不了（权限/占用）只记为该文件失败，不中断整批。进度通过 `GET /v1/imports/batches/{id}` 的 `path_import` 查询，完成后自动提交为任务。
- 桌面端通过 `window.oaDesktop.pathsForFiles(files)`（`webUtils.getPathForFile`）把拖入的文件换成真实路径，通过 `window.oaDesktop.pickPaths({folders})` 打开系统选择对话框；两者只暴露给应用自己的窗口。拖入的“文件夹里的文件”缺少文件夹结构信息，仍走分片上传以保留目录层级；想保留结构且免上传，请用“从本机选择文件夹”。

## 7. 环境变量一览

| 变量 | 默认 | 说明 |
|---|---|---|
| `OA_MAX_UPLOAD_BYTES` | 空（不限制） | 可选：单文件上限（字节） |
| `OA_MAX_BATCH_FILES` | 空（不限制） | 可选：每批文件数上限 |
| `OA_DISK_RESERVE_BYTES` | 536870912 | 始终保留的剩余磁盘空间 |
| `OA_UPLOAD_SESSION_TTL_HOURS` | 24 | 放弃的分片上传多久后清理 |
| `OA_EXTRACT_MAX_BYTES`（worker） | 268435456 | 超过则不做全文提取/OCR，标记为待人工审核；0 = 不设保护 |

Docker 部署可用 `oa-agentctl config set OA_MAX_UPLOAD_BYTES 1073741824` 之类修改（数字，空表示不限制）。
