# 多数据库部署与迁移指南

本文只记录在真实容器上跑通的内容。设计与原理见 `多数据库兼容-设计.md`。

## 1. 支持的引擎与实测版本

| 引擎 | 最低版本 | 实测版本 | 说明 |
|---|---|---|---|
| PostgreSQL | 14 | `postgres:16` | 默认；已有部署无需改动，迁移文件与校验和不变 |
| MySQL | 8.0 | `mysql:8.0`（8.0.46） | InnoDB、utf8mb4（含 4 字节字符）；不支持 5.7 与 MariaDB |
| SQL Server | 2019 | `mssql/server:2019-latest` | NVARCHAR；未测 Azure SQL |
| SQLite | 不支持 | - | 缺 `SKIP LOCKED` 与并发写模型，明确不做 |

未测试：MySQL 8.4、SQL Server 2022、MariaDB、Azure SQL、TLS 的企业 CA 真实证书链（仅有单元级校验）、跨库数据迁移（见 §8）。

## 2. 选择数据库

优先级：环境变量 > 数据目录 `database.json`（设置页保存，待生效）> 内嵌 PostgreSQL（仅 Windows 独立安装）。

```
OA_DB_PROVIDER=postgres|mysql|mssql
OA_DB_HOST OA_DB_PORT OA_DB_NAME OA_DB_USER OA_DB_SCHEMA
OA_DB_PASSWORD  或  OA_DB_PASSWORD_FILE（Docker/Kubernetes secret）
OA_DB_TLS_MODE=disable|require|verify-ca|verify-full
OA_DB_TLS_CA_PEM | OA_DB_TLS_CA_FILE  OA_DB_TLS_SERVER_NAME  OA_DB_TLS_CERT_FILE OA_DB_TLS_KEY_FILE
OA_DB_DSN=mysql://user:pw@host:3306/oa   （完整 URL；旧的 OA_DATABASE_URL 视为 PostgreSQL）
```

环境变量配置时，设置页“数据库”卡片只读并显示原因。配置了外部库时 Windows 独立安装不会启动内嵌 PostgreSQL。

## 3. 专用库与最小权限

OA Agent 要求专用数据库（PostgreSQL 可用专用 schema），不会碰无关表。目标中若存在非 OA 的表，校验会直接拒绝；账号权限过大只告警。把下面的 `<强密码>` 替换后由 DBA 执行。

PostgreSQL：
```sql
CREATE ROLE oa LOGIN PASSWORD '<强密码>' NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE DATABASE oa OWNER oa ENCODING 'UTF8';
REVOKE ALL ON DATABASE oa FROM PUBLIC;
```
MySQL 8.0：
```sql
CREATE DATABASE oa CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'oa'@'%' IDENTIFIED BY '<强密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES, LOCK TABLES ON oa.* TO 'oa'@'%';
```
SQL Server 2019：
```sql
CREATE DATABASE oa COLLATE Chinese_PRC_CI_AS;   -- 或企业标准排序规则
GO
CREATE LOGIN oa WITH PASSWORD = '<强密码>', CHECK_POLICY = ON;
USE oa;
CREATE USER oa FOR LOGIN oa;
ALTER ROLE db_datareader ADD MEMBER oa;
ALTER ROLE db_datawriter ADD MEMBER oa;
ALTER ROLE db_ddladmin  ADD MEMBER oa;
```
初始化完成后可收回 DDL 权限（MySQL：REVOKE CREATE, ALTER, DROP, INDEX；SQL Server：移出 db_ddladmin），升级时再临时授予。

## 4. TLS

`disable` 不加密；`require` 加密但不校验证书；`verify-ca` 校验证书链；`verify-full` 另校验主机名（可用 `server_name` 覆盖）。CA 以 PEM 提供，可选客户端证书。生产环境建议 `verify-full`。

## 5. 初始化与升级（需管理员批准）

- 命令行：`go run ./cmd/migrate -dir ../migrations`（只打印 DDL 预览）；加 `-apply` 才执行；含 `-- oa:destructive` 的迁移还需 `-allow-destructive`。
- 设置页：保存配置 -> “预览并初始化库结构”显示 DDL 数量与确认令牌 -> “批准并执行”。
- 部署级批准：`OA_AUTO_MIGRATE=1`（Docker 默认设置）。隔离与版本检查先于任何建表。
- 失败安全：PostgreSQL / SQL Server 使用事务 DDL，失败整体回滚；MySQL 的 DDL 会自动提交，因此用步骤标记表实现续跑并检测中断（dirty）状态。迁移互斥：PG advisory lock / MSSQL `sp_getapplock` / MySQL `GET_LOCK`。`*.down.sql` 永不自动执行。

## 6. Docker（Linux）使用已有数据库

### 6.1 由安装器完成（推荐）

`install.sh` 的向导里选「使用已有的 PostgreSQL / MySQL 8+ / SQL Server 2019+」，或无人值守时用 `--db postgres|mysql|mssql` + `--db-host/--db-port/--db-name/--db-user/--db-tls/--db-ca-file/--db-schema`，密码只写在 `--config` 文件（权限 600）里。安装器在**安装任何东西之前**做这些事（详见 `部署指南-Linux.md` §14）：

1. 先在本机检测数据库服务（5432/3306/1433 的监听者、systemd 单元、数据库容器），只作为候选列出，**不连接、不试凭据**；
2. 用 `oa-agent-api` 镜像里的 `oa-admin db-check` 验证你填的设置：连通性、版本、权限、隔离性、目标是否为空库或只含 OA 表。密码只经标准输入传给检查容器，不进命令行参数、容器环境、日志或屏幕；失败时给出原因并让你选重试/修改/中止；
3. 通过后显示 DDL 预览（迁移数、语句数、计划指纹），**第二次明确确认**后才执行 `oa-admin db-init --apply --plan <指纹>`（指纹不符即拒绝，保证执行的正是你看过的 DDL）。无人值守不替你批准 DDL：表结构由 API 首次启动时按部署级批准（`OA_AUTO_MIGRATE=1`）创建；
4. 写入 `.env`（0600）：`COMPOSE_FILE` 末尾追加 `docker-compose.external-db.yml`，`OA_DB_PROVIDER/HOST/PORT/NAME/USER/PASSWORD/SCHEMA/TLS_MODE`，有 CA 时复制到应用数据目录 `db-ca.pem`（容器内 `/data/db-ca.pem`，`OA_DB_TLS_CA_FILE`）。不再创建 PostgreSQL 数据目录。

限制与要点：

- 主机不能填 `localhost`/`127.x`（数据库客户端运行在容器里，那里的 localhost 是容器自己）。数据库在**同一台服务器**上时填 `host.docker.internal`（该层给 api 加了 `extra_hosts: host.docker.internal:host-gateway`）或本机内网地址，并且数据库必须监听该地址（只监听 127.0.0.1 的数据库容器连不上；PostgreSQL 还要在 `pg_hba.conf` 放行 Docker 网段）。
- 密码只接受可打印 ASCII，且不含空格和单引号 `'`（`.env` 的写法限制）；`.env` 里写成 `OA_DB_PASSWORD='…'`。
- 目标库里**已经有 OA Agent 的数据**（表结构状态 ok/需升级）时，必须提供当初的 `OA_SECRET_KEY`（交互输入，或配置项 `secret_key_file=<权限 600 的文件>`）；安装器绝不会在旧数据上生成新密钥，没有原密钥就拒绝。
- 需要 Docker Compose 2.24+（该层用了 `!reset`），不满足时预检失败并只要求升级 compose 插件。
- `oa-agentctl backup` 在外部库模式下**不含数据库**（只含 `.env`、密钥、归档文件，并明确警告）；数据库请用引擎自带工具备份；`restore` 不会动外部数据库，也不会把内置库的 dump 还原到外部库安装里。
- 验证范围：PostgreSQL 在真实容器上做过端到端（见 `部署指南-Linux.md` 开头的验证说明）；MySQL 与 SQL Server 通过 `oa-admin db-check` 同一份 `dbadmin` 代码（其真实引擎测试见 §1）和安装器脚本里的 shim 验证，**没有**对它们重做安装器端到端。

### 6.2 手工方式（等价）

在 `.env` 的 `COMPOSE_FILE` 末尾追加 `docker-compose.external-db.yml`，并设置 `OA_DB_*`（见 §2）。该层把自带的 postgres 服务放进永不启用的 profile，因此不会启动；需要 Docker Compose 2.24+。已用 `docker compose config` 校验服务列表只剩 api 与 worker。手工方式下可以先单独运行检查：

```bash
printf '%s\n' "$DB_PASSWORD" | docker run --rm -i --add-host host.docker.internal:host-gateway \
  -e OA_DB_PROVIDER=postgres -e OA_DB_HOST=db.example.com -e OA_DB_PORT=5432 -e OA_DB_NAME=oa -e OA_DB_USER=oa -e OA_DB_TLS_MODE=require \
  --entrypoint oa-admin <仓库>/oa-agent-api:<标签> db-check --password-stdin       # 只读：检查连接/权限/隔离性
# 预览 DDL；确认后用同一指纹执行：db-init --password-stdin --apply --plan <指纹>
```

## 7. 备份与恢复

数据库备份用各引擎自带工具（`pg_dump`、`mysqldump --single-transaction`、`BACKUP DATABASE`），文件目录另行备份。切换数据库前必须备份；新配置只在重启且通过校验、获批后生效，原库数据不会被删除。

## 8. 跨库数据迁移：未提供

本版本没有实现 PostgreSQL / MySQL / SQL Server 之间的数据搬迁（阶段 2），界面也不提供该入口。设置页保存的新数据库配置对已有数据的安装需要显式确认，并且不会自动搬数据；换库请使用空库新装，或自行用引擎工具迁移后再切换。

## 9. 已知限制

- 只有真实容器上测过的组合才保证可用（§1）。
- 搜索忽略大小写但不折叠重音；MySQL/MSSQL 的 JSON 以文本方式读取后在 Go 中解析。
