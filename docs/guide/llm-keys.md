# 配置大模型密钥

大模型是**可选**的。不配置时使用离线规则（按文件名和正文关键词识别，不联网，不需要密钥）。配置后，大模型通过只读工具读取文件并给出分类建议，最终执行仍由确定性代码完成。

入口：“设置 → 识别引擎”（企业版里全局配置仅管理员；操作员是否可配“个人大模型”由管理员的 AI 使用策略决定）。企业版初始化向导最后一步也可配置。

![设置页的大模型卡片（演示数据）](/screenshots/14-settings-llm.png)

## 简单模式（默认）

选服务商 → 登录或粘贴密钥 → 自动测试连接并选好模型 → 一次点击“保存并启用”。Base URL、模型列表、视觉识别、自定义服务只在“高级设置”里。配置保存在数据库，API Key 以 AES-GCM 加密，页面永远不显示已保存的密钥；保存后热生效，无需重启。

内置预设：DeepSeek（推荐）、通义千问、OpenAI、Ollama（本机，无需密钥）、OpenRouter、自定义。Anthropic、Gemini、Kimi、智谱、SiliconFlow 等没有内置预设，可用“自定义（OpenAI 兼容）”手动填写 Base URL 和模型名（要求服务提供 `/chat/completions`，并支持工具调用）。

## 哪些是自动的，哪些不能自动

| 步骤 | OpenRouter | DeepSeek / 通义千问 / OpenAI | Ollama |
|---|---|---|---|
| 创建 API Key | **自动**：登录并点“授权”后，OpenRouter 为本应用生成专用 Key | **必须你自己做**：这些平台没有面向第三方应用的授权接口 | 不需要 |
| 填入密钥 | 自动（服务端加密保存，浏览器拿不到） | 半自动：复制后在应用提示里点“使用这个密钥”；也可手动粘贴 | — |
| 测试连接、取模型列表、选推荐模型 | 自动 | 粘贴后自动 | 点“检测”后自动 |
| 保存并启用 | 授权完成即已启用，默认模型 `openrouter/auto` | 点一次“保存并启用” | 点一次 |

### 为什么不能全自动

项目只使用服务商**公开提供给第三方应用**的授权流程：不抓取登录页、不自动化浏览器登录、不保存用户密码、不复用其他应用（Claude Code、ChatGPT、Copilot CLI 等）的订阅令牌。核查（2026-10-24，来自公开文档与搜索）的结论：

| 平台 | 结论 |
|---|---|
| OpenRouter | 有 OAuth 授权码 + PKCE（S256）流程，兑换后返回用户专属 Key；**已实现** |
| Anthropic | 无。开发者须用 Console 的 API Key；Claude.ai 账号 OAuth 仅限其自有应用，条款不允许第三方代用户走订阅凭据 |
| OpenAI | 只有平台页创建的 API Key；“Sign in with ChatGPT”不向第三方发放 Key（官方页面对自动抓取返回 403，结论未能逐页核实） |
| Google Gemini | OAuth 只产出访问令牌，需自建 Cloud 项目与同意屏幕；不实现 |
| DeepSeek、通义千问、智谱、SiliconFlow | 文档只有手动创建 API Key，没有第三方授权登录 |
| Moonshot / Kimi | 开放平台用 API Key（结论来自第三方指南，未逐页核实） |

没有合规流程的平台，界面只提供“打开密钥页面”链接和手动粘贴。

## OpenRouter 账号登录授权

点“登录 OpenRouter，自动完成设置”→ 在 OpenRouter 官方页登录并点 Authorize → 服务端换取专用 Key 并自动测试连接 → 设置页显示“已为你创建专用 Key：名称（••••尾号）”。

- 原理：PKCE S256，无客户端密钥；`state` 单次有效、10 分钟过期、绑定发起用户；授权码与 `code_verifier` 只在服务端。
- **Windows 桌面版**：回调为 `http://127.0.0.1:<端口>/v1/llm/oauth/callback`，授权页在应用自带的窗口里打开，完成后窗口自动关闭。
- **企业 / 网页版**：必须设置 `OA_PUBLIC_URL`（回调为 `OA_PUBLIC_URL` + `/v1/llm/oauth/callback`），否则返回 `OAUTH_PUBLIC_URL_REQUIRED`；反向代理不能拦截该回调路径。无需配置任何客户端 ID / 密钥。
- 断开只会删除本应用保存的密钥；本应用**无法**代为在 OpenRouter 吊销，请到 <https://openrouter.ai/settings/keys> 删除。
- 默认模型 `openrouter/auto` 会路由到不同模型，识别需要工具调用；连接测试提示不支持时，到高级设置里“获取模型列表”改选明确支持工具调用的模型。

## 应用内密钥窗口（桌面版）

DeepSeek / 通义千问 / OpenAI 卡片的主按钮“打开向导窗口，一步步带你拿到 Key”会在应用自带窗口里打开服务商**真实的密钥页**，右侧是分步指引（登录 → 进入 API keys → 创建，名称建议 `OA Agent` → 复制）。窗口还提供“管理密钥”视图：重新测试、更换密钥、换服务商、删除密钥（先确认）。

应用自动做的只有：打开起始页、按网址推进步骤、检查剪贴板、识别 OpenRouter 回调、把你确认的密钥交给设置表单、取模型列表与测试连接、清空剪贴板。登录、注册、验证码、点“创建”、点“复制”都必须你自己做。

隐私与安全：

- 应用不读取、不注入脚本、不截图、不自动点击服务商页面，也读不到其 Cookie、表单和密码。
- 只读**剪贴板文本**：仅在向导窗口有焦点时每 700 ms 检查，只有文本完全符合该服务商密钥格式才提示，面板只显示尾号；你点“使用这个密钥”后才填入，之后会清空剪贴板里的这把密钥。
- 导航只允许白名单域名（`https`、默认端口）；不在名单的跳转被拦截并说明，可改用系统浏览器。例如 Google 单点登录的域名未加入白名单，可改用邮箱登录。
- 每个服务商一个独立持久分区，“退出登录并清除本窗口数据”可清空。

网页版没有这个窗口：服务商页面在新标签页打开，指引显示在设置表单旁；回到页面时若剪贴板里是该平台格式的密钥，会出现需要点击确认的“粘贴这个密钥”条。

## 失败与重试

任何服务商调用失败（测试连接、取模型列表、登录后的自动测试、归档时识别）都会用白话说明原因和 HTTP 状态，并区分是否值得重试：

| 现象 | 处理 |
|---|---|
| 401 / 403 | Key 无效或无权限，重新复制或更换（不会自动重试） |
| 404 | 地址或模型不存在，检查 Base URL 与模型名 |
| 429 | 限速或额度；接口带 `Retry-After` 时界面显示倒计时 |
| 5xx、超时、连不上 | 服务商故障或网络问题 |

- **自动重试**：识别过程对 429 / 5xx / 网络错误自动指数退避重试，默认 3 次（起始 500 ms，每次加倍并带抖动，单次最长 8 s）；`Retry-After` 超过 8 秒时不再等待，把倒计时交给界面。
- **一键重试**：设置页的“重试”按钮原样重复失败的动作，不需要重新输入。归档任务里因大模型错误失败的文件，可在任务页重试：只重新识别失败的文件，已成功的结果保持不变（`POST /v1/tasks/{id}/retry`）。

## 安全要点

- 更换服务商（Base URL）后必须重新输入密钥，不会把旧服务商的密钥发给新服务商。
- 公网地址必须是 https（只有本机 / 内网允许 http）；链路本地与云元数据地址一律拒绝；不跟随重定向。
- 密钥不进日志、审计和诊断报告。加密密钥在 `data/secret.key` 或由 `OA_SECRET_KEY` 提供，务必备份。
- 视觉识别（高级，默认关闭）会把页面图片发给模型服务商，涉密文件请勿开启。
